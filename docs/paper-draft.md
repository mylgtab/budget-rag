## 摘要（中文草稿）

检索增强生成把「取多少上下文」当成固定超参，但真实系统的预算是有限的、且问题难度差异极大。
本文把检索深度选择写成一个**预算约束下的子模最大化问题**，并给出三个可检验的理论结论：
贪心分配合乎 1−1/e 近似、查询改写的最优门控是一个由预算影子价格决定的阈值、
级联检索的最优策略是一条置信度阈值链。

在 500 条评测上，按此框架实现的系统在 200 token 预算下取得 **0.946** 的召回；
与 5 个基线对比，在 **126 token** 的平均成本下达到 **0.960** 召回，
高于近似 CRAG 的 0.925（179 token）与纯向量检索的 0.910（115 token），
全部差异经配对 bootstrap 与 McNemar 检验显著（p<0.05）。

在 LongBench 两个检索子集上召回 0.995/1.000；在三个多跳生成基准上，
检索带来的正确率提升在两种模型（API 大模型与本地 4B 模型）上一致成立。
人工标注（200 条、双人 kappa 0.67）显示自动指标偏保守，本文报告的所有召回为质量下界。

**关键词**：检索增强生成；上下文预算；子模最大化；自适应检索；成本感知

## Abstract (English, `[草稿 v0.1]`)

Retrieval-augmented generation treats the amount of retrieved context as a fixed
hyperparameter, although real budgets are finite and query difficulty varies by orders
of magnitude. We formulate retrieval-depth selection as **budget-constrained submodular
maximization**: each retrieval action — taking another chunk, switching to hybrid
retrieval, rewriting the query, adding a second hop — carries a cost and a marginal
quality gain, and a policy is a subset of actions under a budget. Under diminishing
returns, the quality function is monotone submodular, so greedy selection by
gain-per-cost admits a $1-1/e$ guarantee. The same view yields two implementable
consequences: whether query rewriting pays off is governed by the shadow price of the
budget rather than a fixed rule, and the optimal cascade is a chain of confidence
thresholds.

We build a reproducible system from this framework. On 500 evaluation queries it attains
**0.960** recall at an average context cost of **126 tokens**, compared with 0.925 at
179 tokens for a corrective-retrieval baseline and 0.910 at 115 tokens for dense
retrieval; all differences are significant under paired bootstrap and McNemar tests
($p<0.05$), and the advantage persists under repeated subsampling. Recall reaches
0.995 and 1.000 on two LongBench retrieval subsets. On three multi-hop generation
benchmarks, retrieval improves answer accuracy consistently for both a hosted
large model and a locally deployed 4B model. Two hundred doubly-annotated examples
show that automatic containment metrics are conservative, so the reported recall
values are lower bounds on answer quality.

**Keywords**: retrieval-augmented generation; context budget; submodular maximization;
adaptive retrieval; cost-aware inference

## 1 引言 `[草稿，v0.2]`

检索增强生成（RAG）已经在开放域问答、文档助理和代码检索中成为标准做法。
这些系统普遍共享一个未加审视的默认设定：**上下文长度是固定超参**。
工程上通常取 top-k = 3 或 5，或直接填满模型的上下文窗口。
但真实请求的难度分布极宽——「ETag 是什么」与「比较强缓存和协商缓存
在长连接场景下的取舍」所需的信息量差一个数量级。固定预算因此同时造成两种浪费：
简单问题买多了，复杂问题买少了。

已有的自适应工作从两个不同角度回应了这个问题。Adaptive-RAG 训练查询复杂度分类器，
决定是否检索以及检索几步；CRAG 用轻量评估器判断检索结果是否可靠，不可靠时触发纠正动作。
两者都提升了「检索行为」与「问题」的匹配度，但都**把预算当成外部给定的常数**：
分类器决定深度，却不回答「在 200 token 的预算里，第一块给谁、第二步要不要改写」。
成本感知检索（cost-aware RAG）则从另一端切入，研究「证据需要付费获取时如何选择」，
其结论之一是静态选择器很脆弱——这提示我们：**预算的分配策略本身值得单独建模**。

本文把检索深度选择写成一个**带预算约束的集合选择问题**。我们把每个可执行的检索动作
——取一块上下文、切换到混合检索、改写查询、跨跳补检索——视为带成本 $c(a)$ 与质量增益
$g(a\mid S)$ 的元素，检索策略即预算 $B$ 下的子集 $S$。在「边际收益递减」这一条可实证检验的
假设下，质量函数成为单调子模，于是适用经典的近似保证：按边际收益/成本比排序的贪心策略
可获得 $1-1/e$ 近似。由此我们还得到两个可直接落到实现里的结论：查询改写是否划算取决于
预算的影子价格（而非固定规则），级联检索的最优策略是一条置信度阈值链。

我们把上述框架实现为一个可运行系统，并在 500 条评测、5 个基线上验证。在 **126 token**
的平均上下文成本下，系统取得 **0.960** 的召回，高于近似 CRAG 的 0.925（179 token）
与纯向量检索的 0.910（115 token）；配对 bootstrap 与 McNemar 检验显示与全部基线的差异
均显著（$p<0.05$）。在 LongBench 的两个检索子集上召回达到 0.995 与 1.000，
在三个多跳生成基准上，检索带来的正确率提升在 API 大模型与本地 4B 模型上一致成立。
200 条双人标注显示自动指标偏保守，本文报告的所有召回均为质量下界。

**贡献**：

1. 把预算约束下的检索深度选择形式化为**子模最大化**问题，并给出贪心策略的近似保证
   （第 3、5 节）。
2. 推导出**改写门控的最优阈值形式**——由预算影子价格决定，而非固定阈值，
   并用成本敏感性实验验证阈值随单价单调下移（第 5、6.7 节）。
3. 实现一个**可复现的预算感知检索系统**，在同等成本下召回高于 5 个基线，
   差异统计显著（第 4、6 节）。
4. 通过跨语料与跨模型验证表明结论不依赖单一数据集或单一模型（第 6.4、6.5 节）。

## 2 相关工作 `[草稿 v0.1，引用条目见 docs/citations.md]`

检索增强生成把参数化记忆与可更新的外部证据结合起来 [Lewis 等, 2020]，其检索深度在多数系统中
是一个超参：固定取 top-$k$ 段落后整段拼入上下文 [Robertson & Zaragoza, 2009; Karpukhin 等, 2020]。
这一默认在上下文廉价的时代是合理的——多取几段，代价近似为零。代价后来换了地方：
位置敏感性实验显示，同一段证据落在上下文的不同位置会带来两位数的准确率差异 [Liu 等, 2024]，
于是「多取」不再等价于「更强」，「取多少」与「放哪里」都变成了需要分配、而非调参的资源。
相关工作沿四条线回应了这个问题（2.1–2.4），2.5 讨论级联与阈值这一决策形式的来源，
2.6 给出本文的位置。

### 2.1 自适应检索

**FLARE** [Jiang 等, 2023] 把「何时检索」绑定到生成过程：当下一段生成出现低置信度 token 时，
以它为查询向前检索，形成前瞻式、按需触发的多轮检索。**Self-RAG** [Asai 等, 2024] 更进一步，
用一组自反思 token 把「是否需要检索」「检索片段是否相关」「答案是否有支持」写进生成序列，
端到端训练模型自行决定检索时机与采纳程度。**Adaptive-RAG** [Jeong 等, 2024] 走分类器路线：
训练查询复杂度分类器，把问题分到不检索、单步检索、多步检索三档，由复杂度选择检索深度。

这三项工作共同把检索行为从固定管线变成按查询决定的决策，但它们优化的是决策的正确性而非代价：
预算在模型之外给定，分类器回答「该走哪一档」，不回答「在 200 token 里第一块给谁、第二步要不要改写」。
此外它们的触发信号来自生成侧自评或问题文本本身，需要额外的推理输出或训练；
本文的门控只用检索分数的相对间隔 $\gamma$（4.3 节），是已有检索过程中免费可得的一个标量，
其阈值由预算的影子价格解出（命题 2），单价变化时可按公式平移（6.7 节）。

### 2.2 纠正式检索

**CRAG** [Yan 等, 2024] 在检索与生成之间插入轻量检索评估器，把结果判为正确、错误或模棱两可，
分别触发「直接使用」「丢弃后改走网络检索」「两者并用」三种纠正动作，是把检索质量问题
当作异常来修复的管线式方案。后续工作沿同一思路加入细化验证、迭代检索与自适应纠错。

这条路线承认了「检索会失手」这一事实，代价是把纠正写成条件分支：是否纠正由评估器的判别决定，
与纠正本身值不值钱无关。本文把纠正动作（改写、跨跳补检索、重排）并入同一个动作集，
用边际收益/成本比排序决定是否执行——预算宽时它们被自动选中，预算紧时被自动跳过，
不需要一条单独的纠正阶段。因此两种做法不是替代关系：CRAG 的评估器可以直接充当
本文动作集里「是否执行纠正」的先验，用来给出更准的 $g(a\mid S)$。

### 2.3 成本感知检索

成本感知检索从另一端切入：若每条证据的获取本身要付费（付费检索器、外部 API、人工标注），
选择器就必须在效用与花费之间权衡。已有工作指出，静态选择器在负载变化时很脆弱，
预算增加也不必然带来质量提升 [Cost-Aware RAG, 2026]，这说明分配策略需要显式建模，而非调参。

本文处理的是另一种成本：**上下文占用**。它不出现在检索账单上，却同时被三件事定价——
按 token 计费、注意力预算、位置敏感性 [Liu 等, 2024]。两者可以写进同一个背包问题：
把动作成本从标量换成向量（获取费 + 占用费），单维预算换成多维预算。
本文只解占用这一维，因此结论与上述工作可合并，而非相互竞争。

### 2.4 上下文压缩与选择性增强

另一条线在「已经取回的内容」上做减法。**LLMLingua** [Jiang 等, 2023] 用小模型的困惑度估计
token 重要性并压缩提示；**LongLLMLingua** [Jiang 等, 2024] 引入问题感知压缩以缓解长文档的
信息丢失；**RECOMP** [Xu 等, 2024] 训练抽取式与生成式压缩器，把多段证据压成摘要。
这类方法提高单位 token 的信息密度，其权衡是压缩率与保真度。查询改写一侧，
**HyDE** [Gao 等, 2023] 用生成的伪文档替代原查询做稠密检索，属于改写动作的一族。

压缩与本文的预算分配是正交的两层：压缩降低单位 token 的价格，本文决定买多少个单位。
合并时，压缩等价于把每个动作的成本 $c(a)$ 乘上一个折扣系数，既不改变选择问题的结构，
也不改变贪心的最优性条件。本文的多跳实验可视为同一现象的另一面：模型生成的补充查询
优于从上下文抽取专有名词的规则方案（6.5 节）——信息密度更高的动作，边际收益/成本比更高。

### 2.5 级联与阈值决策

「按观测逐级决定是否继续」在统计学中早有最优停止的形式：序贯分析给出，在成本递增、
观测逐级到达的设定下，最优策略是一条阈值——观测足够好就停，不够好才继续 [Wald, 1947]。
这一形式在 LLM 服务中被重新发现：**FrugalGPT** [Chen 等, 2023] 先用便宜模型作答，
再按置信度决定是否升级到更强更贵的模型，在真实计费上验证了阈值式路由的降本效果。

本文的命题 3 把这一形式推广到检索动作：当动作成本递增、收益随置信度单调时，
最优策略同样是一条置信度阈值链，且阈值随预算单调移动。与 FrugalGPT 的差别在约束方向：
它以质量达标为前提最小化花费，本文以预算为约束最大化质量，两者互为对偶，
对偶变量正是本文的影子价格 $\lambda$。这也是本文能把「阈值该设多少」写成可计算的公式、
而不必当作需要搜索的超参的原因。

### 2.6 本文位置

| 方向 | 决策对象 | 预算的角色 | 触发信号 | 与本文的关系 |
|---|---|---|---|---|
| 自适应检索 [Jiang 2023; Asai 2024; Jeong 2024] | 是否检索、检索几步 | 外部常数 | 生成置信度 / 复杂度分类器 | 本文补上「该给多少」 |

合起来看，已有工作分别推进了「要不要检索」「检索得对不对」「证据贵不贵」「上下文能不能删」
四个问题，它们共享一个未展开的假设：**检索行为可以独立于预算来选择**。
本文补的正是这一层——把预算写成显式约束、把影子价格写成可观测量，策略由二者的比值导出，
于是「选哪一档」「要不要改写」「要不要跨跳」在同一个排序规则下被统一解答。

## 3 问题形式化 `[已有，见 docs/theory.md 第 1–2 节]`

- 动作集 $\mathcal{A}$、成本 $c(a)$、质量 $Q(S)$
- 目标：$\max Q(S)$ s.t. $\sum c(a) \le B$
- 假设 A1（边际收益递减）、A2（成本可加）

## 4 方法 `[草稿 v0.2]`

### 4.1 双索引与预算取块

长文档按两种粒度建索引：**句级**（按标点切分，约 15–40 token）与**固定块**（滑动窗口，
默认 200 token、重叠 40）。句级索引在紧预算下更省，因为它不会把无关句子一起带进来；
固定块在宽预算下更连贯。系统按目标预算自动选择：`ctx < 500` 用句级，否则用固定块。

取块时按检索得分降序累积，直到已选块的总 token 达到预算 $B$ 即停，
**不做固定 k 截断**——这是「预算」而非「条数」成为一等公民的关键。

### 4.2 级联路由

路由按「每千 token 的允许成本」分档：预算极紧（< 0.002 元）走 BM25 单路取 1 块；
中等走 BM25 取 2 块；宽裕（≥ 0.01 元）走混合检索取 5 块。分档边界不是拍出来的：
它们是贪心分配的离散化（第 5 节命题 1），在实践中对应「边际收益/成本比」的拐点。

### 4.3 置信度门控的查询改写

改写调用占端到端延迟的一半以上（6.8 节），因此只在必要时触发。系统先做一轮廉价检索，
计算 top-1 与 top-2 得分的相对间隔

$$\gamma = \frac{s_1 - s_2}{s_1}.$$

当 $\gamma < \tau$ 时认为检索「没把握」，触发查询改写并用「原问题 + 改写词」重检索。
阈值 $\tau$ 的最优值由预算影子价格决定（命题 2），默认 0.25 对应「改写成本约等于
一次强检索」的定价；6.7 节的敏感性实验验证了 $\tau$ 随单价上升而下移。

### 4.4 多跳扩展

对需要两处证据的问题，第一跳之后把「问题 + 已检索摘要」交给模型，让它输出还缺什么信息，
再用「原问题 + 补充查询」做第二跳，两轮结果按块去重合并。实验表明，
模型生成的补充查询优于从上下文抽取专有名词的规则方案（6.5 节）。

## 7 讨论 `[草稿 v0.1]`

> 注：本节引用的 4.x 为 `docs/report.md` 的实验节号，并入第 6 节时统一改写。

### 7.1 预算是接口，不是超参

把预算写成约束、而不是一个调好的 $k$，换来三件可迁移的东西。

**其一，影子价格变成可读的配置参数。** $\lambda$ 的含义是「每多花一单位预算买到的质量」，
它把「该取几块」翻译成「这一单位预算还值不值」。6.7 节的敏感性实验给出了它的可观测后果：
单价系数从 0.25 升到 2 时，最优阈值从 0.25 掉到 0，即系统自行判定「这个价格下改写不划算」。
对工程而言，这意味着可以按 SLA 配置预算（每条查询多少 token、多少钱），
而不必为新模型或新单价重扫一遍超参。

**其二，门控的收益必须按负载的难度分布报告。** 全量 500 条上改写触发率 38%，
即省掉 62% 的改写调用；但前 50 条（偏难）触发率 76%，接近全量改写（4.10 节）。
改写本身是延迟的主要来源（+0.9 s，p95 +1.4 s，6.8 节），所以门控省下的是
「与批次难度成反比」的那部分延迟。本文据此给出一个可复现的口径：报告门控收益时同时报告触发率，
否则同一个方法在两批数据上会给出相反的结论。

**其三，扩展点只有动作集一处。** 新增一个动作（重排、跨跳、压缩器）只需给出它的成本 $c(a)$
与边际收益 $g(a\mid S)$，排序规则与近似保证都不动。重排实验正好说明这条扩展的正确用法：
候选池 8、预算 300 token 时重排带来 0.0 pt（候选全塞得下，没有选择压力）；
候选池 30、预算 150 token 时带来 +5.5 pt（4.x，报告 4.7）。收益来自「截断」而不是动作本身，
与本文框架的解释一致。

### 7.2 适用条件

本文的收益来自**难度的异质性**与**预算的紧张**，两个条件同时成立时收益最大，只看其中一个是误用。

**预算区间。** 粒度实验给出边界：预算 ≤500 token 时，句级索引在同等召回下省 15%–50% 上下文；
>800 token 时固定块反超（4.5 节）。原因不难理解——预算放开后「选哪些」的自由度被稀释，
任何策略都能取到大块，分配技巧失去用武之地。本文的战场是紧到中等预算。

**瓶颈位置。** 本文的结论建立在「检索是瓶颈」之上。三个多跳基准上检索命中率 0.50–0.65，
而 4B 模型的正确率只有 0.20–0.40（4.29 节）：答案片段已经进了上下文，模型却提取不出来。
在这种负载上，继续加大上下文预算的边际收益会被生成侧吃掉，预算应当转向生成侧
（更强的模型、更长的推理、显式的答案抽取提示）。这不是方法的失效，而是同一框架给出的
资源再分配结论：$\lambda$ 说的是钱该投到边际收益最高的地方，当检索不是那个地方时，它自然指向别处。

**负载同质性。** 在问题与语料高度同质的合成集上，除固定浅检索外的所有策略差异都落在
置信区间内（4.4 节）。同质负载下预算调度的收益趋近于零，固定 top-$k$ 就够用；
本文的方法在异质负载上才拉开差距。

### 7.3 成本模型的边界

**单价不是常数。** A2 假设每个动作的成本固定且与顺序无关。实际计费有阶梯折扣、缓存命中与批处理，
$\lambda$ 会随负载变化。这不需要改模型，只需把 $\lambda$ 当作运行时可观测量：
6.7 节的扫描是它的时不变近似，线上系统可以按更短的窗口更新它。

**token 估算有系统偏差。** 同一段 prompt，tiktoken 估算 131 token，API 返回实际计费 71 token，
高估 84%（4.16 节）。本文的预算控制用估算值，因此报告的 token 成本是上界：
换用真实分词后，同等召回下的真实上下文成本更低。方向对结论安全，绝对值需要打折。

**成本可以是向量。** 延迟与钱不是同一个维度。改写占端到端延迟一半以上，而它的 token 成本
几乎可以忽略；若把两者一起计入，$c(a)$ 应取向量，最优策略从单条阈值链变成帕累托前沿上的
阈值链，贪心的保证从 $1-1/e$ 松弛为逐维度的松弛界，但排序规则不变。
多维预算是本文框架最自然的下一步扩展，不需要新的理论。

### 7.4 与下界的距离

一个便于定位的对照：oracle 显示，在已经知道该取哪一块的前提下，0.958 的召回只需 58 token
（4.30 节）；本文的策略不知道，用 126 token 达到 0.960（6.2 节）。两者口径不完全相同，
但差值指向同一件事——剩余的成本差距主要来自**选择误差**，而不是上下文不够用。
这解释了本文的方向是继续改进 $g(a\mid S)$ 的估计、细化选择粒度，而不是继续加大预算；
也解释了 4.30 节那个反直觉的结果：更多标注没有提升路由准确率，
因为标签本身依赖「检索到了什么」，而不只依赖问题措辞。
