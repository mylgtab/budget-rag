## 做不到 / 需要你决定（附解决办法）

| # | 缺口 | 为什么本鲸做不了 | 怎么解决 |
|---|---|---|---|
| 1 | **复现训练版 Adaptive-RAG** | 需要他们训练分类器 + 多跳管线，代码依赖 GPU 和数据预处理 | 拉官方仓库，按 README 在 GPU 上复现；或引用其报告数字并注明「未能完全复现」 |
| 2 | **复现 Self-RAG / CRAG 原版** | 都需要微调的评估器（7B 级），本地无 GPU | 用 API 复现「行为等价」版本并标注为 approximation（本文已这样做，需在论文里明说） |
| 3 | **更多基准**（2WikiMultiHopQA、MuSiQue、NQ） | 需要下载 + 分片 + 生成判定，单次约 2000 次调用 | 按本文脚本改 `--file` 即可，预算约 ¥300–600 |
| 4 | **真实账单** | 只有 API 返回的 token 数，没有发票 | 把 `RAG_PRICE_*` 设成你的实际单价，或用控制台账单截图核对 |
| 5 | **GPU 级延迟** | 单机 CPU + 远程 API | 若要报端到端延迟，需在同一台机器上跑本地模型 |
| 6 | **更大规模人工评估** | 需要真人标注，已有 200 条 + 双人一致性 | 扩到 500 条，或找 3 位标注员算 Fleiss kappa |
| 7 | **投稿本身** | 需要通讯作者账号、单位、APC | 你注册 Springer 账号；FCS 无 APC，Applied Sciences 约 ¥17000 |
| 8 | **理论证明的严格性** | 命题 1 引用了已知定理，但没给出完整证明 | 补 Nemhauser 定理的适用条件检查；命题 2/3 需完整推导 |

## 论文骨架（建议）

1. Introduction：RAG 的固定预算假设不成立；成本应随问题难度分配
2. Related Work：Adaptive-RAG / CRAG / Self-RAG / Cost-Aware RAG
3. Problem Formulation：预算约束下的子模最大化（theory.md 第 1–2 节）
4. Method：双索引、级联、改写门控、多跳（每个都对应一个动作）
5. Theory：三个命题 + 可检验预测
6. Experiments：主结果、基线、消融、显著性、跨语料、人工、忠实度
7. Discussion：负结果（PRF、第 0 级、贪心反例）
8. Limitations：合成数据、单模型、近似基线
