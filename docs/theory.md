# 预算约束下的检索策略：形式化草稿

> 目的：把「级联检索」从工程经验提升为可分析、可证明的策略，
> 这是投 Frontiers of Computer Science 这类期刊的必要条件。

## 1 问题定义

一次查询 $q$ 上可执行一组**检索动作** $a \in \mathcal{A}$，例如：

- $a_1$：BM25 取 1 块
- $a_2$：BM25 取 3 块
- $a_3$：混合检索（BM25 + 向量）
- $a_4$：查询改写后重检索
- $a_5$：LLM 重排

每个动作有**期望成本** $c(a) > 0$（元）与**期望质量增益** $g(a \mid S)$，
其中 $S \subseteq \mathcal{A}$ 是已选动作集合（增益依赖已有上下文）。

目标：

$$
\max_{S \subseteq \mathcal{A}} \; Q(S) \quad \text{s.t.} \quad \sum_{a \in S} c(a) \le B
$$

$Q(S)$ 用答案质量度量（contain / EM / F1 或人工分），也是单调不减的：
多加动作不会让质量变差（上下文只增不减，或至少不替换）。

## 2 两条假设

**A1（边际收益递减）** 对任意 $S \subseteq T$ 与 $a \notin T$：

$$
g(a \mid S) \;\ge\; g(a \mid T)
$$

直觉：第一块上下文最有用，后面越来越水。这条使 $Q$ 成为**子模函数**。

**A2（成本可加且与顺序无关）** $\sum_{a\in S} c(a)$ 只依赖集合，不依赖执行顺序。

## 3 命题与证明思路

**命题 1（贪心的近似保证）**
在 A1、A2 下，$Q$ 单调子模。按**边际收益/成本比**降序贪心选动作，
在预算 $B$ 下得到 $1-1/e$ 近似（Nemhauser–Wolsey–Fisher, 1978 的预算版，Khuller 等 1999）。

*含义*：不需要精确求解背包，一个排序规则就有理论保证。

**命题 2（改写门控的最优阈值形式）**
设不改写的质量为 $q_0$，改写后为 $q_1$（$q_1 > q_0$ 概率为 $p$），改写成本 $c_r$。
则当且仅当

$$
p \cdot (q_1 - q_0) \;>\; \lambda \, c_r
$$

时改写划算，$\lambda$ 是预算的影子价格（拉格朗日乘子）。
等价地：**置信度低于某阈值才改写**，阈值由 $\lambda$ 决定。

*含义*：现在的 0.25 是拍出来的，理论给出它应该随单价/预算变化。

**命题 3（级联的最优策略是置信度阈值）**
若动作成本递增、收益随置信度单调，则最优策略是「置信度落在区间 $[\tau_i, \tau_{i-1})$ 走第 $i$ 档」，
即一条阈值链。这解释了为什么级联有效，也说明阈值应随 $B$ 单调移动。

## 4 可检验的预测

| 编号 | 预测 | 检验方法 |
|---|---|---|
| P1 | 质量随成本的曲线是凹的 | 扫预算，看二阶差分是否 ≤ 0 |
| P2 | 贪心分配与暴力最优的差距小（< 2pt） | 小规模动作集上暴力枚举对比 |
| P3 | 最优改写阈值随单价上升而上升 | 改造成本系数，看阈值移动方向 |
| P4 | 按查询自适应分配优于全局固定预算 | 混合难度工作负载下对比 |

## 5 实测证据（100 条，bge-m3）

单动作表现：

| 动作 | 召回 | 平均 token |
|---|---|---|
| BM25 取 1 块 | 0.790 | 23 |
| BM25 取 3 块 | 0.890 | 69 |
| BM25 取 6 块 | 0.910 | 138 |
| 混合取 3 块（alpha=0.2） | **0.900** | **69** |
| 改写 + 混合取 3 块 | **0.960** | 151 |

**P1（边际收益递减）：成立。** 贪心路径的边际收益/成本为
`0.0338 → 0.0016 → 0.0004 → 0 → 0`，单调下降，符合 A1。

**P2（贪心接近最优）：基本成立，但有一个反例。**

| 预算（等效 token） | 贪心 | 暴力最优 | 差距 |
|---|---|---|---|
| 60 | 0.790 | 0.790 | 0 |
| 120 | 0.900 | 0.900 | 0 |
| **200** | **0.900** | **0.960** | **+0.060** |
| 300 | 0.960 | 0.960 | 0 |
| 500 | 0.960 | 0.960 | 0 |

预算 200 时贪心输 6pt：它按比例先选了便宜的 `hybrid_k3`，剩余预算不够升级到改写，
而直接选 `rewrite_k3`（151 token）反而更好。**这正是「贪心是近似而非最优」的具体体现**，
也说明实际系统里需要「够不够跨档」的判断，而不是纯按比例排序。

顺带一个观察：`hybrid_k3`（0.900 / 69 token）**严格优于** `bm25_k3`（0.890 / 69 token），
同成本下更好的选择；`bm25_k6`（0.910 / 138）性价比最差。

## 6 与已有工作的关系

- Adaptive-RAG 用分类器决定深度，没有预算项；本文把预算显式写进约束。
- CRAG 的纠正动作是「发现问题再修」，本文把它纳入统一的目标函数，作为动作之一。
- Cost-Aware RAG 处理「证据要花钱买」，本文处理「上下文 token 要花钱占」，
  两者可以合并成同一个背包问题，这是可以主张的一般性。
