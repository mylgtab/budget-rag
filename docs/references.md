# 参考资料与设计借鉴

## Ponytail（DietrichGebert/ponytail，MIT）

> 让 AI 助手像「最懒的资深工程师」：最好的代码是你没写的代码。

它的核心是一条**懒惰阶梯**——写代码前逐级自问，一旦某级成立就停：

1. 这功能需要存在吗
2. 代码库里已经有了吗
3. 标准库能做吗
4. 平台原生支持吗
5. 已装的依赖里有吗
6. 能一行写完吗
7. 才轮到「最小可行实现 + 一个小测试」

配套原则是 **"lazy, not negligent"**：校验、错误处理、安全、无障碍，一律不许省。
它公布的对照数据是：代码 −53%、时间 −41%、成本 −26%、token −45%，
同时「有风险逻辑带测试」的比例从 68% 提到 98%。

## 我们借了什么

| Ponytail 的做法 | 我们在 budget-rag 里的对应实现 | 结果 |
|---|---|---|
| 懒惰阶梯：先问「需要吗」 | 检索阶梯的第 0 级：不检索直接答 | **不成立**：contain 0.11 vs 0.92，这类知识库离不开检索 |
| 「先看已有的」 | 双索引 + 预算取块：先句级、再固定块，按预算停 | 有效，4.5/4.6 节 |
| 「能一行就别写类」 | 零依赖优先：hash embedding、纯 Python BM25、SVG 手绘 | 克隆下来不装任何包就能跑 |
| 「省 token 但不省验证」 | 省上下文，但保留 contain/EM/F1 与人工标注校准 | 4.9 节 |
| 公开基线与相对提升 | 报告里所有结论都给基线对照 | 全文 |

## 没借、但值得考虑的

1. **`shortcut:` 债务台账**：他们把「有意偷懒的地方」写成注释，用命令收成清单。
   我们可以用 `TODO(cost):` 标记近似实现（比如字数/1.5 的旧估算），定期回收。
2. **成本带（band）**：在界面顶部常驻显示本轮成本与 token。
   我们的 `trace` 已有这些字段，缺一个可视化。
3. **单文件规则集**：他们整个项目就是一个 SKILL.md。
   我们的规则散在 README/report/AGENTS.md，可以考虑合并。
