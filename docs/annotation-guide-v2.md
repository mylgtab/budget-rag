# 标注说明（v2 · 补充 2/3 分边界规则）

## 你要做什么

表里 100（或 30）条问答，每条看 `system_answer` 和 `reference_answer`，
在 `score` 列填 **1 / 2 / 3**，拿不准就在 `note` 写一句。

**独立判断，不要互相商量。** 只看意思，措辞不同不扣分。

## 三步判定法

### 第一步：判对错

`system_answer` 是否与 `reference_answer` **矛盾**？

- 矛盾 / 答非所问 / 空白 / 只写「不知道」→ **直接 1 分**，不用再看完整性
- 不矛盾 → 进入第二步

### 第二步：数关键要素

把 `reference_answer` 拆成**可验证的要素**，逐个数：

| 要素类型 | 例子 |
|---|---|
| 主体 | 「强缓存」「B+ 树」「Redis」 |
| 条件 / 前提 | 「3.7 之后」「在预算宽裕时」「只允许浏览器」 |
| 数量 / 上限 | 「一张表只能有一个」「每秒一千」 |
| 动作 / 结论 | 「不发请求」「减半」「保证插入顺序」 |

### 第三步：按缺失情况给分

- **要素齐全** → **3 分**
- **缺 1 个及以上「条件/数量」类要素** → **2 分**（方向对，但不完整）
- 答案**多出错误信息**（不是无关但正确的补充）→ 最多 **2 分**
- 只说对了主体、没说出结论 → **1 分**

## 边界规则（这次重点）

| 情况 | 给几分 |
|---|---|
| 只换措辞、同义改写 | 3 |
| 少了「很」「通常」「一般」这类修饰词 | 3（不算要素） |
| 少了「3.7 之后」「只能一个」「必须加盐」这类**可验证条件** | **2** |
| 答案正确但**只覆盖问题的一半** | 2 |
| 补充了一句**正确但无关**的信息 | 3（不扣分） |
| 补充了一句**错误**的信息 | 2 |
| 与参考答案说法相反 | 1 |

## 三个例子

**例 1（3 分）**
- 参考：强缓存命中时浏览器不会发请求，直接读本地副本。
- 答案：强缓存命中时不会发请求，直接用本地缓存。
- 判定：只换了措辞，要素齐全 → **3**

**例 2（2 分）**
- 参考：Redis 的分布式锁用 SET NX EX 实现，必须设置过期时间防死锁。
- 答案：用 SET NX EX 实现分布式锁。
- 判定：丢了「必须设置过期时间」这个条件 → **2**

**例 3（1 分）**
- 参考：B+ 树的叶子之间用链表相连，所以范围查询很快。
- 答案：因为 B+ 树是平衡树，所以查询快。
- 判定：结论相近但机制说错（不是链表）→ **1**

## 不用做的

- 不用改系统答案，不用查资料，不用管标点和格式
- 拿不准就选 2，并在 `note` 写清缺了哪个要素

## 交付

存成 `annotation_<你的名字>.csv` 发回。**30 条约 25 分钟，100 条约 1.5 小时。**
