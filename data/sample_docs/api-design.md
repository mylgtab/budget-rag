# API 设计

REST 用资源路径加 HTTP 方法表达操作，GET 查询、POST 创建。
GET 应当是安全的，不应有副作用。
PUT 是幂等的全量替换，PATCH 是部分更新。
幂等意味着重复调用结果一致，支付接口必须做到。
分页常用 limit 加 offset，深分页性能差。
游标分页用上次的位置做锚点，深翻页稳定。
HTTP 状态码要语义正确，201 表示创建成功。
错误响应应包含机器可读的错误码和人类可读的说明。
版本号放在路径里最直观，放 header 更符合语义。
限流可以用令牌桶或漏桶算法。
令牌桶允许突发流量，漏桶输出更平滑。
重试要区分错误类型，4xx 通常不该重试。
超时设置要小于上游的等待时间，否则层层堆积。
请求 ID 贯穿全链路，方便排查问题。
大文件上传用分片和断点续传。
接口文档可以用 OpenAPI 自动生成。
兼容性上，新增字段安全，删改字段危险。
幂等键放在 header 里，由客户端生成。
批量接口要有数量上限，避免单次请求拖垮服务。
返回字段裁剪可以显著降低带宽。
