# 测试与工程质量

单元测试验证单个函数或类的行为，运行快、定位准。
集成测试验证多个模块协作，能发现接口约定问题。
端到端测试从用户视角跑完整链路，最接近真实但最慢。
测试金字塔建议单元测试最多，端到端测试最少。
断言要具体，一个测试只验证一个行为，失败时才好定位。
测试应该独立，不依赖执行顺序和外部状态。
把时间、随机数、网络请求抽象成可注入的依赖，测试才稳定。
mock 用来替代外部依赖，过度 mock 会让测试和实现绑死。
覆盖率衡量被执行到的代码比例，高覆盖率不代表测试有效。
分支覆盖率比行覆盖率更严格。
手工构造边界值，是发现 bug 性价比最高的方式。
回归测试用来防止已修复的问题再次出现。
TDD 先写失败测试再实现，能迫使接口先被设计。
日志要带上下文，但不要打印敏感信息。
结构化日志便于检索和聚合，比拼接字符串好。
监控看趋势，告警看异常，两者指标口径要一致。
熔断在依赖持续失败时快速返回，避免雪崩。
重试要加退避和次数上限，否则会放大故障。
幂等设计让请求可以安全重试，常用唯一请求号实现。
灰度发布先让小部分流量验证，再全量。
