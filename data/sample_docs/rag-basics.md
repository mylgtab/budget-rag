# 检索增强生成（RAG）

RAG 先把文档切块并转成向量，检索出与问题最相关的片段，再把片段作为上下文交给模型回答。
这样做的好处是答案有出处，不用把整篇文档塞进上下文，token 成本可控。

分块大小直接影响效果：块太大噪声多，块太小语义不完整。常见做法是 300 到 500 字，
相邻块保留一部分重叠，避免答案被切断。

向量检索擅长语义相近但用词不同的情况，关键词检索（BM25）擅长专有名词和数字。
把两者分数归一化后加权融合，通常比单用一种更稳。

评测常用 Recall@k 衡量检索是否召回到答案所在片段，再用 EM 和 F1 衡量回答质量。
成本要单独统计：每次查询的检索与生成 token 数乘以单价。
