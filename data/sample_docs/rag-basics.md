# 检索增强生成

RAG 先把文档切块并转成向量，检索出相关片段再交给模型回答。
RAG 的好处是答案有出处，不用把整篇文档塞进上下文。
分块太大噪声多，分块太小语义不完整。
常见做法是每块 300 到 500 字，相邻块保留一部分重叠。
重叠能避免答案被切断在块边界。
向量检索擅长语义相近但用词不同的情况。
关键词检索擅长专有名词和数字，BM25 是常用实现。
BM25 依据词频和逆文档频率打分，并对文档长度做归一化。
把 BM25 与向量分数归一化后加权融合，通常比单用一种更稳。
重排模型对候选片段再打一次分，能提升精度但增加成本。
召回率衡量答案所在片段是否进入候选集。
Recall@k 是前 k 个结果里命中答案片段的比例。
EM 是精确匹配，要求答案与标注完全一致。
F1 按词级重合计算精确率和召回率的调和平均。
成本要单独统计，等于检索与生成的 token 数乘以单价。
只提高召回的检索会让上下文变长，反而推高成本。
所以检索深度应该按问题难度动态决定。
路由是先用启发式特征判断问题难度，再选择检索路径。
评测集要覆盖不同难度，否则指标会被简单问题拉高。
每次改动只动一个变量，结果才可解释。
