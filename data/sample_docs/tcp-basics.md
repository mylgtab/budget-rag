# TCP 与网络基础

TCP 三次握手建立连接，目的是确认双方的收发能力并同步序列号。
三次握手的第一个包是 SYN，第二个是 SYN+ACK，第三个是 ACK。
四次挥手断开连接，因为 TCP 是全双工的，两个方向要分别关闭。
TIME_WAIT 状态持续 2MSL，用来保证最后一个 ACK 能被对方收到。
大量 TIME_WAIT 会占用端口，可通过开启 tcp_tw_reuse 缓解。
滑动窗口控制发送方在未收到确认前能发多少数据。
拥塞窗口由发送方维护，根据网络状况动态调整。
慢启动阶段拥塞窗口按指数增长，每轮翻倍。
拥塞避免阶段窗口按线性增长，每轮加一。
快重传在收到三个重复 ACK 时立即重传丢失的报文。
快恢复在快重传后把窗口减半而不是回到一个报文。
Nagle 算法把小包合并发送，会引入延迟，实时场景常关闭。
延迟确认会推迟发送 ACK，和 Nagle 同时开启时可能互相等待。
黏包是应用层看到多条消息粘在一起，根源是 TCP 是字节流没有边界。
解决黏包可以在消息前加长度字段，或使用固定分隔符。
UDP 无连接、不保证顺序，适合实时音视频和 DNS 查询。
QUIC 基于 UDP 实现可靠传输，握手更快且支持连接迁移。
HTTP/1.1 默认长连接，HTTP/2 多路复用同一连接上的多个请求。
HTTP/3 基于 QUIC，避免了 TCP 层的队头阻塞。
CDN 把静态资源缓存到离用户更近的节点，减少回源和延迟。
