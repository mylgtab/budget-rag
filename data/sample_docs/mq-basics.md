# 消息队列

消息队列用于解耦生产者和消费者，削峰填谷。
队列模型每条消息只被一个消费者消费。
发布订阅模型每条消息会被所有订阅者收到。
至少一次投递可能重复，需要消费者做幂等。
最多一次投递不重复，但可能丢消息。
恰好一次投递实现复杂，通常靠幂等加去重表达成。
消费者组让多个消费者并行消费同一主题。
分区内的消息有序，跨分区不保证顺序。
消费者提交位点表示已经处理到哪里。
自动提交位点可能丢消息，手动提交更可靠。
消息积压时增加消费者是常规手段，但受分区数限制。
死信队列存放多次重试仍失败的消息。
重试要加指数退避，避免把下游打死。
消息的 TTL 设置过长会导致积压难以清理。
顺序消息要求同一业务键路由到同一分区。
事务消息用于本地事务与发消息的一致性。
消息去重常用业务唯一键加 Redis 记录。
流量洪峰时可以先写队列再异步处理。
队列的可靠性取决于刷盘策略和副本数。
监控消费延迟比监控队列长度更能反映问题。
