# 性能与可观测性

延迟是单次请求耗时，吞吐是单位时间处理的请求数。
P99 延迟比平均值更能反映用户体感。
平均值会被少数极慢请求掩盖，必须看分位数。
压测要区分并发数和请求速率。
并发数固定时，延迟上升会导致吞吐先升后降。
利特尔法则把并发、吞吐、延迟三者联系起来。
缓存是提升性能最直接的手段。
缓存命中率决定缓存的实际收益。
多级缓存从本地内存到远程缓存逐层兜底。
连接池减少建立连接的开销，但池太小会排队。
慢查询日志是定位数据库性能问题的起点。
索引缺失和全表扫描是最常见的慢查询原因。
N 加 1 查询指循环里逐条查库，应改为批量查询。
异步化能把非关键路径移出主流程。
线程池参数要根据 IO 密集还是 CPU 密集来定。
指标、日志、链路追踪是可观测性的三支柱。
黄金指标包括延迟、流量、错误率和饱和度。
告警要设置静默期，避免告警风暴。
分布式追踪用 trace id 串起跨服务调用。
火焰图用于定位 CPU 热点，比采样日志直观。
