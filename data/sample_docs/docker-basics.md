# Docker 与部署

镜像是由多层只读层叠加而成的文件系统快照。
容器是镜像的运行实例，本质是被命名空间隔离的进程。
镜像层是只读的，容器启动时在最上面加一个可写层。
Dockerfile 里每条 RUN 都会产生新的一层，所以常把多条命令用 && 合并。
把变化频率低的指令放在前面，能复用构建缓存。
多阶段构建用一个大镜像编译、再把产物拷到小镜像里，显著减小体积。
容器删除后可写层的数据就丢了，需要挂载卷持久化。
绑定挂载把宿主机目录直接映射进容器，适合开发调试。
命名卷由 Docker 管理，适合数据库这类需要持久化的场景。
容器的网络默认通过 bridge 网络与宿主机通信。
端口发布用 -p 宿主机端口:容器端口，只写容器端口会随机分配。
容器内进程要监听 0.0.0.0 才能被外部访问，监听 127.0.0.1 只能在容器内访问。
ENTRYPOINT 定义固定入口，CMD 提供默认参数，两者配合使用。
docker compose 用一个 yaml 描述多容器服务及其依赖。
容器之间通过服务名互相访问，compose 内置了 DNS。
.dockerignore 能避免把大文件和无用目录打进构建上下文。
容器以非 root 用户运行能降低被提权的风险。
健康检查通过 HEALTHCHECK 指令声明，compose 可以依赖健康状态启动顺序。
重启策略 unless-stopped 会在异常退出后自动拉起容器。
镜像瘦身可以用 alpine 基础镜像，但要注意 glibc 与 musl 的差异。
