# 数据库索引

B+ 树索引把数据按顺序组织在叶子节点。
B+ 树的叶子之间用链表相连，所以范围查询很快。
B+ 树的非叶子节点只存键，因此一次磁盘 IO 能读入更多键，树高更低。
聚簇索引的叶子节点直接存整行数据，一张表只能有一个。
二级索引的叶子存主键，查其他列要回表。
覆盖索引指查询需要的列都在索引里，可以避免回表。
最左前缀原则指联合索引只有在查询条件从最左列开始时才能用上。
联合索引 (a, b, c) 中，只查 b 或 c 用不上这个索引。
范围查询会中断后续列的索引使用。
索引不是越多越好，每个索引都增加写入成本和存储占用。
写多读少的表要克制索引数量。
区分度低的列建索引收益很小，比如性别字段。
前缀索引只索引字符串的前若干个字符，节省空间但降低区分度。
索引列上使用函数或隐式类型转换会导致索引失效。
like 以通配符开头无法使用普通索引。
order by 的列有索引时可能省去排序步骤。
explain 可以查看查询是否走了索引。
回表次数多时，优化器可能干脆选择全表扫描。
唯一索引在插入时承担唯一性校验，代价是额外的检查。
复合索引的列顺序要按区分度和查询条件设计。
